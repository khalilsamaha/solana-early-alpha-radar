# Native offline handoff integration

Connects the accepted exact-target control and handoff coordinator without
changing either accepted package. The host runner reuses the accepted scanner
image; no rebuild, pull, credential, provider, remote-storage or production action.

The direct/restored actors are source-bound inert image processes, not production
scanner loops. The shared consumer executes the real image-contained shared
adapter, with no source mount. The separate bounded Python owner supplies only
synthetic creation/migration frames. A clean retirement is followed by another
creation event; cleanup failure closes the stream and retains its failed outcome.
All provider/billing/production authority flags remain false.

Native mode verifies fixed image, commands, isolation, UID, readiness, exact
container/PID/start identity and owned cleanup. The Unix peer's credentials and
host parent PID must bind to the container init PID. Socket identity is checked
before consumer start. Restoration requires the original target still stopped,
owner reaped, consumer stopped and original configuration/policy reproduced in
a new inert actor. Every adapter receipt binds the coordinator operation ID;
a separate source-bound plan and detailed observation report are retained.

The owner has a 90-second alarm, CPU/address-space limits, no core dump and Linux
parent-death SIGKILL. It opens only a private Unix listener (or development pipe),
with no upstream implementation. The registry remains consumed after any fault.
Fixture disposal is separate from handoff confirmation and cannot complete pending
operations. All children are reaped; unverified target identity blocks removal.

Five retained cases: normal, cleanup failure, lost owner-start response, lost
shared-stop response and lost restore response. Lost-response faults occur only
after the intended real action and evidence checks. The latter case deliberately
creates a restored inert actor but leaves restoration pending; cleanup does not
rewrite that journal. Expected host total: thirteen owned containers removed.

`check_native.py --development` uses real Python/Node subprocesses and a pipe,
but simulated Docker metadata. Its result is explicitly development-only and
cannot satisfy native host acceptance. The normal CLI requires Docker/Unix and
existing UID/GID 1000 access. Missing prerequisites stop without install, permission
change or fallback. No standalone old image/control batch is repeated.

Private handoff registries use short /tmp paths to meet Unix socket limits. Their
original paths are recorded and preserved; acceptance.zip includes claims and
journals for independent historical replay. Do not move/rearm those registries
or retry a failed attempt. This is not an operational retention mechanism.

Remaining production gates: real scanner/owner configuration and global exclusivity,
provider connection-close evidence, approved production registry/admission and
rollback, live credentials/supervision, variable-session real delivery and approved
capacity/retention and numeric pilot terms. This integrates isolated mechanics;
it does not finish production readiness or start a pilot/study.

# Receipt-complete evidence handoff (offline)

An orchestration archive alone does not contain the admission, cleanup and
completion receipts stored beside it. `delivery.export` places all seven fixed
roles plus a manifest into one bounded, canonical, uncompressed package. An
independent external SHA-256 is mandatory for verification and restore. Source
hashes bind the reviewed implementation; they are integrity bindings, not a
signature or proof of provenance against someone who rewrites all inputs.

Verification replays the inner evidence on disposable copies, checks exact
preservation/restore reports, and runs the accepted orchestration reconciler
against a temporary reconstruction. That reconstruction is never published as
a runnable service. Restore publishes flat receipts and evidence, never rearming
the consumed admission. A complete replay of a failed unsubscribe is evidence
of that failure, not measurement success. Interrupted shutdown remains quarantined
and requires manual reconciliation, even after successful delivery.

`transfer.rehearse` tests the finalization protocol using an explicitly local
mirror: frozen package, durable one-use intent, upload observation, exact
download, independent restore, then completion last. Interrupted or failed
transfer retains the local package and consumes the control directory. No retry,
overwrite or deletion is attempted. An upload observation cannot establish
successful restoration. A simulated transfer never claims remote preservation.
Keep each control directory for reconciliation; creating a new directory is a
new deliberate test, not a way to resume an uncertain attempt.

The checker uses synthetic pipe fixtures, opens no provider connection, loads
no real credentials, invokes no Docker and changes no production configuration.
Its local mirror is not a B2 adapter. A fixed-destination, bounded B2 delivery
adapter and actual receipt-complete remote acceptance remain pending; the older
fixed-input session round trip is not being repeated here. Ongoing retention,
remote access policy/encryption, production startup/rollback, approved exposure,
actual provider behavior and full R1 acceptance remain open. This increment does
not authorize live collection, ML fitting, CI consolidation or a new effort cap.

Run with the hash-pinned dependency from `r1-data/requirements-wire.txt`:

```sh
python3 -E -s -B -W error::ResourceWarning r1-delivery/check_delivery.py \
  --output-directory /absolute/new/private/output
```

Upload `report.json` and all three `*-package.zip` files. Success is
`offline-delivery-passed-remote-pending`; expected shutdown quarantine is retained.
The packages include only the synthetic fixtures generated by this check.
